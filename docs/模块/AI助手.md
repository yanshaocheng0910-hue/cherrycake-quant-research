# AI 助手｜跨页面的研究能力

[返回作品导览](../作品导览.md) · [指标机器人](指标机器人.md) · [复盘中心](复盘中心.md)

AI 助手不是孤立的聊天页。它嵌在工作台、机器人、复盘、选股、个股深挖与资料阅读之中：简单问题可以直接解释已经取得的事实；需要查询或筛选时调用限定工具；复杂研究才进入有阶段、证据和可恢复状态的任务。市场数字、指标分数和 PEG 计算仍由确定性的业务代码完成，模型负责阅读、组织和提出下一步核对问题。

## 从提问到研究任务

| 使用深度 | 系统先做什么 | 用户看到什么 |
| --- | --- | --- |
| 即时解释 | 读取当前页面、标的、日期及已经显示的事实 | 简短回答，附时间、来源和边界 |
| 受控工具 | 根据意图选择白名单工具，取得行情、板块、指标或资料 | 可追溯的事实包、缺失项和工具状态 |
| 完整研究 | 封存输入事实，进入阶段任务并持续保存事件 | 阶段进度、论证、风险、失败终态与结果入口 |

工具不能超出当前账号的授权范围；模型输出不能直接改写行情、评分或用户条件。长任务失败会显示原因与可恢复状态，不把空内容包装成成功。[查看七阶段个股研究入口](功能索引.md#value)。

## 各页面怎样使用 AI

| 入口 | 用户想问什么 | 哪部分仍由系统确定 |
| --- | --- | --- |
| [工作台](#workbench) | 今天先看什么，市场宽度与风险怎么读？ | 市场统计、交易日与来源由后端给出。 |
| [指标机器人](#robot) | 信号为什么是候选，哪些周期不同向？ | 指标与评分由引擎计算。 |
| [复盘与竞价](#review) | 连板、情绪与次日条件如何核对？ | 复盘样本和时点采集先确定。 |
| [智能选股](#screener) | 把口语想法变成哪些可审核条件？ | 字段白名单、条件确认与最终筛选由系统控制。 |
| [个股深挖](#research) | 财务、行业、风险和反证如何组织？ | 行情、财务、公告先形成事实包。 |
| [资讯、研报与 PEG](#documents) | 资料说了什么，哪些字段缺失？ | 原文、页码、数值计算和适用性由业务层保留。 |
| [全局助手与任务通知](#global) | 切页后怎样继续追问或回到任务？ | 会话、账号、任务状态和模型来源由服务端验证。 |

<a id="workbench"></a>
### 工作台中的 AI

工作台的猫咪助手沿用当前阶段与页面事实：盘前帮助排序要点，盘中解释市场宽度、板块变化，盘后协助把问题转成待验证条件。它只组织已采到的统计，不凭空写一只“应买”股票。[工作台公共组件与助手截图](../new_screenshots/WB-COMMON-01-b.png) · [工作台结构](工作台.md)。

<a id="robot"></a>
### 指标机器人中的 AI

机器人将周期、指标家族、信号阶段和风险快照交给助手；助手解释支持项、冲突项与下一步观察点。用户可以再回到[图表和逐 K 状态](指标机器人.md)，检查回答是否真正对应同一日期与周期。模型不计算也不修正正式信号。

<a id="review"></a>
### 复盘与竞价中的 AI

助手可以归纳市场宽度、封板质量、历史分位和明日条件，但不能替代[复盘中心](复盘中心.md)的分母和来源说明。竞价样本缺失时只能说“未通过核验”；下一交易日是否兑现，仍要看真实时点采集。[复盘页局部图](../new_screenshots/REV-01.png)。

<a id="screener"></a>
### 智能选股里的 AI

用户可以说“找近期放量但别追太高、行业里相对强的股票”。AI 先把口语映射为平台允许的字段与候选条件，页面列出每个条件的含义、来源和可能的歧义；用户确认后才运行筛选。模型不能绕过字段白名单，也不能直接输出未经扫描的候选作为命中结果。[自然语言与条件选股截图](../new_screenshots/SHOT-018.png) · [选股模块](功能索引.md#screener)。

<a id="research"></a>
### 个股深挖的阶段任务

完整研究把公司资料、行业、估值、财务、现金流、技术位置、风险和反证分阶段呈现。任务保存阶段状态、事实包与输出；用户可以从结论返回证据，看到不足之处，而不是只拿到一段漂亮摘要。[个股深挖截图](../new_screenshots/SHOT-030-b.png) · [个股研究](功能索引.md#value)。

<a id="documents"></a>
### 资讯、研报与 PEG 的资料解释

研报阅读保留 PDF 原文、提取正文与页码定位；PEG 页面先校验价格、预期 EPS 与增长数据，缺项时明确“不计算”。AI 可以解释资料和口径，不能虚构缺少的分析师一致预期。[资讯与研报索引](功能索引.md#information) · [估值说明](功能索引.md#value)。

<a id="global"></a>
### 全局入口与任务通知

用户从当前页发问，长任务完成后由通知返回结果；切换页面时仍携带账号和任务身份，不能借通知读取别人的记录。全局助手复用站内同一个猫咪入口，而不是在每页复制一套聊天数据。[工作台助手图](../new_screenshots/WB-COMMON-01-b.png)。

<a id="models"></a>
## 模型来源与权限

![三种 AI 来源：站长提供、我的模型 API、我的 WorkBuddy](../new_screenshots/SHOT-023.png)

用户首先选择三种相互独立的来源：**我的模型 API**、**站长提供**、**当前电脑的 WorkBuddy**。选中站长来源后，才出现站长明确资助的子模型；未授权账号看不到站长密钥或本机订阅。当前电脑 WorkBuddy 仅在本机已登录、可验证回答且本机入口满足条件时使用，公网不能扫描访客电脑。

站长资助的 WorkBuddy 可按已授权规则免费优先；只有这一条来源失败且允许兜底时，才明示切换到站长 DeepSeek。使用自己的 API 或明确选择本机 WorkBuddy 时，不会暗中消耗站长额度。任务开始与继续时服务端重验授权，前端选择只是操作入口，不是权限来源。

技术上，FastAPI 负责会话与工具边界，后台任务记录状态和证据，SQLAlchemy/SQLite 保存账号配置与任务索引，密钥加密保存；前端展示实际选中的模型、授权与失败原因。更多整体链路见[架构与数据链路](../系统架构与数据链路.md)。
