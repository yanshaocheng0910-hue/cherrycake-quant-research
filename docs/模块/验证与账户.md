# 验证与账户｜把观察留下来，再检查它

[作品首页](../../README.md) · [复盘中心](复盘中心.md) · [选股与个股研究](选股与个股研究.md) · [AI 助手](AI助手.md)

研究流程需要一个“留下记录”的地方，也需要一套不偷看未来的验证方式。这里把**自选、模拟交易、回测、信号质量和数据源状态**放在同一章：自选保存个人对象，模拟记录虚拟执行，回测重放规则，质量统计检查信号样本，数据状态解释为什么某条结论可用或暂缺。各自的数据口径不同，不能把模拟盈亏、历史收益和正式交易混成一条曲线。

| 入口 | 保存或检验什么 | 边界 |
| --- | --- | --- |
| [自选中心](#watchlist) | 当前账号的标的、分组与备注 | 与其他账号隔离 |
| [模拟交易](#paper) | 虚拟订单、持仓、盈亏 | 不接真实交易接口 |
| [回测中心](#backtest) | 历史规则、交易和风险 | 只用当时可见数据 |
| [信号质量](#quality) | 信号后表现与无条件基准 | 样本少不下强结论 |
| [数据状态](#status) | 来源、时间、字段与失败原因 | 在线不等于字段可用 |

<a id="watchlist"></a>
## 自选中心｜让“我关注的”只属于当前账号

用户可以搜索、添加、删除股票，设置分组和备注，再从清单进入机器人、选股或个股研究。持仓星标是个人整理方式；它不等于真实持仓同步，也不代表系统会自动推送交易提醒。跨账号读取被服务端会话边界阻断，页面按钮不是权限凭证。

自选与策略条件通过 SQLAlchemy/SQLite 保存账号归属，服务端读写都按当前身份过滤。以下实拍把策略入口、股票搜索和个人列表放在同一局部图中。

<a id="paper"></a>
## 模拟交易｜记录假设中的执行，而非真实下单

模拟账户提供虚拟资金、买卖记录、持仓和盈亏回看。用户可以检验自己的研究计划有没有被执行、模拟买卖价是否合理，以及成本是否吞掉预期收益。页面明确写着“非真实下单”；行情用于估值，不保证可成交价格。

模拟记录与实际交易账户隔离，也不复制用户的真实资金或委托。账号权限和当前开放范围以运行网站为准。

![模拟账户：虚拟资金、下单与持仓](../new_screenshots/SHOT-052.png)

<a id="backtest"></a>
## 回测中心｜让规则在同一段历史里比较

先选择股票、日期、周期和信号方案，再对照收益、回撤、胜率、逐笔交易与同期持有表现。候选、正式确认和生命周期风控是不同的执行口径，应分别展示；回测开始前说明决策时点、成本、滑点、不可成交与数据覆盖。

系统按历史时间顺序重建当时可见的信号，不把下一根 K 线或事后修订的数据送回过去。pandas/NumPy 处理时间窗口与统计，ECharts 展示曲线，服务端保留参数、公式版本、数据来源和失败状态。一个好看的收益曲线不替代逐笔证据。

![回测：参数、同窗对照和关键风险](../new_screenshots/SHOT-055-a.png)

[收益曲线、分布与逐笔交易局部图](../new_screenshots/SHOT-055-b.png)和上图配套，方便回到每一次进出时的依据。

<a id="quality"></a>
## 信号质量｜把分数放回真实样本

质量页按标的、周期和历史窗口统计信号后的若干 K 线表现，同时显示无条件基准、样本量和覆盖范围。候选、确认、结束与延续属于不同阶段，不能混成同一个胜率。样本很少、日期未成熟或字段缺失时，页面降低解释强度并保留原因。

用户可从汇总表下钻到事件列表，再返回[机器人](指标机器人.md)核对当时的图表；回测与信号质量互相校验，但并非同一统计问题。

<a id="status"></a>
## 数据状态与权限｜先确认结论能否成立

行情、历史回补、资讯、财务和模型服务各自可能处于完整、部分、过期、未授权或失败状态。“服务在线”与“目标字段确实取得”分开核对；页面说明节点、来源时间和具体受限原因，不以零值掩盖缺失。

站长授权模型、用户自备 API 与当前电脑 WorkBuddy 有不同的账号边界；[AI 来源与权限](AI助手.md#models)解释用户如何选择。内部 Provider 清单、账号密钥与运行诊断不放入公开展示图。当前动态站由 Windows 本机和 Cloudflare Tunnel 接入公网，Tunnel 不是运行服务器。
