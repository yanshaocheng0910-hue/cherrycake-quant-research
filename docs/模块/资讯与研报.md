# 资讯与研报｜为研究补上可追溯的外部资料

[作品首页](../../README.md) · [工作台盘前](工作台.md#pre) · [个股研究](选股与个股研究.md#stock-research) · [AI 助手](AI助手.md#documents)

这一组页面负责回答“发生了什么、消息从哪来、和研究对象有什么关系”。它由**市场简报、资讯雷达、产业信号、资讯榜单、实时动态和研报中心**构成。简报先给阅读顺序，雷达与榜单负责寻找条目，产业页面追踪连续资料，实时动态保留时效，研报中心让用户回到文档原文。新闻热度本身不等于买卖信号。

| 入口 | 主要作用 | 继续到哪里 |
| --- | --- | --- |
| [市场简报](#brief) | 一页看当天值得核对的事实 | 盘前或复盘 |
| [资讯雷达](#radar) | 按来源、主题和标的筛消息 | 原文与个股研究 |
| [产业信号](#industry) | 跟踪有日期的行业数据与趋势 | 板块中心 |
| [资讯榜单](#ranking) | 发现关注度上升的议题 | 来源复核 |
| [实时动态](#live) | 看事件何时发生、是否仍新鲜 | 市场或标的详情 |
| [研报中心](#reports) | 检索、阅读并引用 PDF 文档 | AI 阅读与研究任务 |

<a id="brief"></a>
## 市场简报｜先定阅读顺序

每日简报把当天的重要市场事实集中呈现，按交易时段提供开盘前、集合竞价、连续交易和收盘复盘入口。标题保留原始来源与时间；页面的聚合时间和新闻发布时间分开显示，避免把“刚读取”误认为“刚发生”。用户可以继续进入[工作台](工作台.md)看市场结构，而不是仅凭一条标题改变策略。

前端展示主题与状态，后端从允许的来源规范化条目、去重和排序；缺少原文或来源不明时降低解释强度。下图是一张局部实拍，覆盖事实列表、来源时间与交易时段入口。

<a id="radar"></a>
## 资讯雷达｜从一条消息回到原文

资讯雷达按股票、板块、主题、来源与发布时间筛选。用户先查事实，再跳到相关公司、板块或[个股研究](选股与个股研究.md#stock-research)；需要 AI 摘要时，回答应能返回条目和原文链接。重复转载不能被当成多条独立证据，旧消息不会因缓存刷新变成“实时”。

这一页的公开实拍图仍待补。展示仓库先保留功能说明，不用新闻宣传图代替真实页面。

<a id="industry"></a>
## 产业信号｜把行业数据放进时间轴

产业页关注比单条新闻更慢的变化，例如 GPU 链、台系月营收、DRAM 与商品价格趋势。用户要能同时看到指标名称、来源、统计日期、更新频率和覆盖缺口，再决定是否把趋势带到[板块中心](市场发现.md#plates)。非实时资料可以用于方向观察，但不能冒充实时成交数据。

某项数据需要第三方授权、原站限制抓取或没有连续历史时，页面直接说明“暂不可用”或仅提供已验证的公开趋势。不同资料走各自的数据适配和缓存，不把不同单位、市场和时区强行拼成同一个分数。授权未定的能力不在本仓库宣称完成；页面公开实拍待补。

<a id="ranking"></a>
## 资讯榜单｜热度是线索，不是结论

榜单把同日反复出现的主题、行业和公司整理为阅读入口，并保留上榜依据。用户点开以后仍需看原始条目、影响对象与发布时间。后端做去重和聚合，前端给出可筛选的排行；“讨论多”只说明关注度，不自动提高机器人评分。页面公开实拍待补。

<a id="live"></a>
## 实时动态｜明确事件时效

动态流按时间滚动，展示更新时点、来源与受影响标的。刷新失败、来源停更和旧缓存分别标记，避免旧信息以新时间重新出现。用户可由事件进入[异动中心](市场发现.md#alerts)核对价格和信号，但新闻本身不触发真实订单。页面公开实拍待补。

<a id="reports"></a>
## 研报中心｜文档、解析文字和 AI 阅读分层

研报中心按公司、行业、标题、发布日期和来源检索。阅读时先看 PDF 原文，再看可搜索的解析正文；提问或对比结论时保留页码、原句位置和未解析页。模型可以帮助提炼观点、比较不同报告，但不能把未覆盖的财务字段写成“研报显示”。

PDF 文件、文本抽取和问答任务分层处理；文档无法打开、页面抽取失败或权限不足时都要显式显示。公开展示先说明阅读路径，具体页面实拍待补。[了解 AI 怎样读取研报](AI助手.md#documents)。

资料最终回到研究链：[市场发现](市场发现.md) → [资讯核对](#brief) → [个股研究](选股与个股研究.md#stock-research) → [明日验证](复盘中心.md#tomorrow)。
