## 一、项目定位

车厘子蛋糕机器人是一套面向 A 股日常研究的全栈量化平台。它把实时行情、指标机器人、市场复盘、板块结构、策略选股、个股研究、估值、资讯、研报、回测、模拟和 AI 辅助研判连接成一条可回看的研究流程。

```text
发现市场 → 研究标的 / 主题 → 形成条件 → 历史验证 → 模拟执行 → 回看证据
```

产品重点不是只输出一个买卖标签，而是把数据来源、事实日期、指标状态、信号过程、风险边界、样本口径和不可用原因放在结果旁边，让用户知道“结果是什么、依据在哪里、还能不能继续用”。

## 二、系统框架

```text
行情与资讯源
    ↓
数据接入、来源标记、缓存与历史回补
    ↓
指标引擎 / 复盘计算 / 估值 / 策略 / 回测
    ↓
FastAPI 服务与异步研究任务
    ↓
HTML + CSS + JavaScript + ECharts 页面
    ↓
用户筛选、下钻、验证、模拟和 AI 追问
```

| 层级 | 使用技术 | 在项目中的职责 |
| --- | --- | --- |
| 前端结构与交互 | HTML、CSS、JavaScript | 页面结构、筛选、状态、表格、任务进度、响应式布局和页面跳转 |
| 数据可视化 | ECharts | K 线、指标叠加、资金曲线、收益曲线、热力图和统计图 |
| 后端服务 | Python、FastAPI、Uvicorn | 接口、异步任务、研究计算编排和结果返回 |
| 实时行情 | Futu OpenD | 报价、快照和多周期 K 线接入 |
| 历史数据 | baostock | 交易日历史数据和日线回补路径 |
| 数据持久化 | SQLAlchemy、SQLite | 行情事实、策略、研究任务、模拟记录和结果状态 |
| 研究计算 | 多周期指标、信号生命周期、PEG、回测 | 把原始数据整理成可检查的研究结果 |
| AI 辅助 | OpenAI 兼容 API、BYOK、本机 Agent | 基于平台事实做只读总结、比较、研报阅读和追问 |
| 当前动态访问 | Windows 本机、Uvicorn、Cloudflare Tunnel、HTTPS | 本机运行应用，Tunnel 将固定域名接入本机服务 |
| 后续迁移方向 | 境外 Linux 服务器、nginx、systemd | 可选的长期动态部署方案；不是当前已完成的部署 |
| 静态展示 | GitHub、Cloudflare Pages（可选） | 承载本展示仓库；不替代动态业务服务器 |

## 三、专业名词怎么理解

| 名词 | 项目中的通俗解释 |
| --- | --- |
| API | 前端向后端请求结构化数据的通信入口。 |
| 异步任务 | 回测、研报解析和 AI 研究先创建任务，再显示进度和读取结果。 |
| 多周期 | 同一标的同时从分钟、小时、日线、周线等时间尺度观察。 |
| 信号生命周期 | 信号从候选、确认、保持到撤回或结束的完整过程。 |
| 多周期共振 | 多组周期出现同方向证据时，作为额外上下文，而不是简单相加。 |
| As-of | 截至某个历史时点真正可见的数据，避免未来信息倒灌。 |
| 回测 | 在明确的历史窗口和执行假设中重放规则，查看交易与风险。 |
| PEG | 将市盈率和盈利增长率结合的估值辅助指标，缺失或不适用时不强行解释。 |
| BYOK | Bring Your Own Key，用户使用自己的模型 API Key，和共享模型额度隔离。 |
| 事实投影 | 按当前问题从完整平台事实中选出模型真正需要读取的部分。 |
| 数据降级 | 实时路径不可用时读取合适的历史或缓存，或者明确显示不可用，不拿旧数据冒充实时。 |

完整解释见[技术栈与专业名词](docs/技术栈与名词.md)。

## 四、日常使用流程

```text
开盘前 / 开盘后：市场简报 → 工作台 → 确认指数、情绪和数据状态
盘中：自选 / 板块 / 排行榜 → 指标机器人 → 异动中心
收盘：A 股复盘中心 → 首板 / 连板 / 情绪周期 → 保存明日验证条件
研究：选股 → 个股研究 / PEG → 资讯 / 产业信号 / 研报 → AI 研判
验证：回测 → 质量统计 → 模拟 → 回到原始事实和数据覆盖
```

### 指标机器人公开到什么程度

展示材料会讲清楚：

- 多个指标家族分别观察趋势、动量、资金和结构。
- 系统先整理基础方向，再通过分层评分表达证据强度。
- 多周期共振提供额外上下文，风险门槛和手动过滤影响确认状态。
- 用户最后可以回到关键价位和逐 K 快照核对原因。

展示材料不会公开：

- 具体公式、权重、阈值和内部参数。
- 完整策略配方和可以直接复制的决策规则。

这样既能说明工程能力和使用方式，也不会把产品内部策略直接写成公开教程。

### 复盘中心为什么要层层展开

复盘中心不是单一页面卡片，而是：

```text
复盘中心
  → 复盘看板
    → 市场宽度 / 情绪横截面 / 赚钱效应 / 亏钱效应 / 晋级率
  → 盘面数据 / 首板分析 / 五日热度 / 涨停样本统计
  → 连板天梯 / 情绪周期 / 明日验证 / 竞价核验
  → 口径与证据 / 页内 AI 复盘
```

每一层都有自己的说明和截图位置，用户可以先看总览，再进入数据、结构、跨日验证和证据。

## 六、截图怎么补

1. 将真实截图放入 `screenshots/`。
2. 文件名严格按照[截图清单](docs/截图清单.md)使用。
3. 打开 `index.html`，同名 PNG 或 WebP 会自动替换对应占位。GitHub 首页 README 的“截图”文字不会自动变成图片，补图时也需要将对应文字替换成 `![功能截图](screenshots/文件名.png)`；这一步由维护展示仓库的人完成。
4. 新增功能时，只更新这个独立展示仓库的说明、截图清单和页面数据，不修改主项目源码、工作日志或原 README。

截图中不要出现 API Key、密码、验证码、服务器 IP、Cookie、内部账号或未授权数据。图片可以是 PNG 或 WebP，但要保证关键功能文字可读。

## 七、数据和部署边界

实时行情可用，不代表财务字段、资讯和研报接口也可用。系统按具体能力显示来源、事实时间、缓存或回补状态；无法保证口径时应显示不可用或受限，不用旧数据伪装成实时。

AI 结果、原始事实、来源时间和缺失项分开呈现。普通问答、事实扫描和完整研究任务的工具范围不同；AI 只做辅助研判，不执行真实下单。

本仓库可以发布到 GitHub，也可以作为静态站发布到 Cloudflare Pages。静态发布只承载展示材料；动态业务服务仍需要实际运行的应用、数据库和数据源节点。

## 八、项目边界

- 这是展示和教学材料仓库，不是业务源码仓库。
- 不上传主项目、数据库、密钥、生产配置或账号信息。
- 不为了简历反向改造主产品，不把规划中的能力写成已经上线的事实。
- 真实功能和后续截图以实际产品为准，展示页面只负责解释、索引和呈现。
