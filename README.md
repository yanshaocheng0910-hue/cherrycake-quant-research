## AI 助手｜贯穿各个领域的智能层

AI 助手是产品的一层能力，不等于“AI 研判”一个页面。它在工作台、指标机器人、复盘中心、选股、个股研究、资讯研报和任务通知中以不同深度出现：简单问题直接引用系统事实，复杂问题才启动有阶段、有工具、有状态的研究任务。

### 从即时问答到研究任务

先接收页面上下文和用户意图，再决定是事实查询、解释、筛选还是完整研究。

只调用白名单工具读取行情、板块、指标、财务、公告或已有研究记录；工具结果先形成事实包，模型不能自行补写价格和评分。

复杂研究进入任务队列，按阶段推进并保存进度、事件、证据、失败原因和可恢复状态。

回答带有数据时间、来源和边界；模型不可用时显示真实失败或回退结果，不把空结果包装成成功。

| 领域 | 用户看到的 AI 交互 | 确定性部分与 Agent 部分 | 界面示例 |
| --- | --- | --- | --- |
| 工作台 | 询问“今天先看什么”、解释市场宽度和盘前状态。 | 市场统计由后端计算；AI 负责把事实组织成阅读顺序和风险提示。 | AI-02｜工作台助手 |
| 指标机器人 / QQQ | 询问信号、四家族评分、周期共振和指标怎么用。 | 指标与评分由引擎产生；AI 读取快照并解释，不创造信号。 | AI-01 / ROBOT-01 |
| A 股复盘 / 竞价 | 根据事实询问情绪、连板、竞价兑现和明日验证。 | 复盘统计与时点采集确定；AI 负责归纳、对照和提出复核问题。 | AI-03 / WB-AUC-01 |
| 智能选股 | 用口语描述策略、主题或板块条件。 | 意图解析和条件审核由 AI 辅助；最终候选必须经过白名单字段和确定性筛选。 | AI-04｜自然语言选股 |
| 个股研究 | 启动七阶段深挖，查看结论、证据缺口和风险。 | 行情、财务和公告先封存；Agent 分阶段生成七个结果区并轮询状态。 | AI-05｜研究任务 |
| 资讯 / 研报 / PEG | 要求解释资料、指标口径或缺失原因。 | 资料来源、字段完整性和 PEG 计算确定；AI 只做有来源的解释。 | AI-06｜资料解释 |
| 全局助手与通知 | 在页面底部继续追问，或从任务完成通知返回结果。 | shell.js 轮询任务状态；助手沿用当前账号、页面和模型路由。 | AI-07｜任务通知 |

## 指标引擎与评分系统｜从源码研究到产品信号

指标机器人采用“源码研究 → 数值核验 → 生产适配 → 家族评分 → 生命周期 → 质量评估”的工程链。指标源码工作区保留 dk 主图、MACD、MACDF、O 趋势和幻影主力的源码、版本、截图、读数和候选否决记录；网站仅接入证据充分、口径明确的部分。

### 四个证据家族与评分约束

这四类证据分别回答趋势、动量、量价支持和趋势背景问题。网站展示各家族的贡献及相互冲突；内部公式、参数、权重和阈值不在公开仓库提供。

| 证据家族 | 在页面中帮助判断什么 | 使用边界 |
| --- | --- | --- |
| DK 主图 | 买卖点、最近方向与趋势状态。 | 以可核验的图表和事件为依据，不把未经证实的公式接入正式信号。 |
| 动量家族 | 交叉、柱体阶段和动量衰减。 | 相关指标先合并解读，避免同一类证据重复计票。 |
| 幻影主力 | 区间位置、量价实体及低位脉冲。 | 柱形不等于真实机构资金。 |
| O 趋势 | 趋势带的扩张、收缩与背景风险。 | 不能单独生成正式入场信号。 |

## 工作台｜四个阶段与公共组件

工作台按交易日顺序组织多块研究面板。盘前、竞价、盘中、盘后各自承载对应的数据与任务，并共享市场背景、自选、板块、事件、快捷研究和状态说明。

工作台是产品首页，也是日内研究的总编排器。四个阶段构成一级模块，市场卡片、竞价核验、板块轮动、核心股、事件流和明日验证分别归入对应阶段。用户先看阶段概况，再进入具体分支，研究顺序保持连续。

### 四个一级阶段总览

| 一级阶段 | 总体作用 | 下属功能范围 |
| --- | --- | --- |
| 盘前 | 把上一交易日的事实和隔夜信息整理成开盘前核对顺序。 | 盘前要点、自选相关、公司公告、全球与政策、市场宽度、资金预览。 |
| 竞价 | 把开盘前五个时点的实际采集结果与昨日条件连接起来。 | 时点快照、证券范围、板块映射、自选竞价、失败重试、开盘后回看。 |
| 盘中 | 观察实时市场变化，并定位值得下钻的板块、核心股和事件。 | 指数成交、热力图、板块轮动、资金流向、题材热度、事件流、电报、连板天梯。 |
| 盘后 | 把当天事实收回并转化为下一交易日可以验证的条件。 | 涨跌停回收、短线情绪、板块落盘、事件归档、明日验证、复盘/选股/AI 入口。 |

### 盘前：开盘前核对清单

所属层级｜工作台 → 盘前。本分支的作用是把盘前阶段的市场事实组织成可直接执行的研究动作。

把昨日下午形成的条件带到今天开盘前，先核对市场背景，再看个人关注标的。

- 盘前要点：显示上一交易日的市场宽度、成交、情绪和重要风险，给出“今天先看什么”的顺序。

- 自选相关：只列当前账号关注的股票、持仓或板块，直接跳转机器人、板块和异动详情。

- 公司公告：集中呈现自选公司的公告、业绩和重要事件，保留发布时间和原文入口。

- 全球与政策：将隔夜外盘、政策和大宗商品变化作为背景，不把新闻标题直接当成交易信号。

- 盘前数据状态：显示实时、缓存、历史回补或暂缺，避免把旧数据当作开盘前最新数据。

技术栈与实现｜FastAPI 聚合盘前摘要接口；pandas 对齐交易日和时间；前端用卡片分区与更新时间标签表达状态。

### 盘前：市场宽度与资金预览

所属层级｜工作台 → 盘前。本分支的作用是把盘前阶段的市场事实组织成可直接执行的研究动作。

开盘前先看全市场的广度、行业宽度和资金分位，判断今日更可能是普涨、分化还是收缩。

市场宽度与结构

- 指数与成交预览：同时看主要指数、成交额和涨跌家数，不以单一指数代替市场。

- 行业宽度：比较行业内部上涨比例、强弱和样本数量，找出“指数涨但内部弱”的情况。

- 资金分位：显示资金集中方向及历史位置，明确是快照、趋势还是历史分位。

- 关注板块入口：从预览卡进入板块中心，并携带日期、板块和观察窗口。

技术栈与实现｜结构化市场摘要由后端统一时间口径；ECharts 负责宽度和分位图形；卡片链接保留 query 上下文。

### 竞价：五个时点与采集状态

所属层级｜工作台 → 竞价。本分支的作用是把竞价阶段的市场事实组织成可直接执行的研究动作。

集合竞价卡把采集时点、样本范围和失败状态分开显示；目前历史日期仍缺完整的 09:25 真实快照，因此不展示竞价强弱结论。

- 时点状态：逐个显示已采、部分或未采；只有真实快照可用时才展示价格、涨跌和成交。

- 范围核对：标注全市场、沪深样本或部分股票，避免把局部成功误写成全市场结果。

- 昨日条件回放：把“明日验证”规则带入页面；没有真实竞价样本时不输出命中判断。

- 失败和重试：显示失败时点、错误原因、已完成部分和可再次采集入口；不把失败显示成 0。

- 开盘后回看：竞价结束后仍保留原始快照，供复盘与次日验证使用。

技术栈与实现｜后端按交易日和时点返回采集状态与范围；前端以状态标签区分缺失、部分与可核验样本。

- 公式与分母：解释涨跌、晋级率、炸板率、历史分位等。

- 证据链接：回到原始明细、公告或研报页面。

技术栈与实现｜口径说明与结果同接口返回；schema 记录单位和 as-of 时间；来源链接不由模型生成。

### 复盘中心的跨日流程

- 收盘后：锁定当日市场样本，生成涨跌、涨停、炸板、跌停和短线情绪。

- 复盘时：从看板下钻到首板、五日热度、连板和历史分位，形成可解释的判断。

- 保存时：把判断改写成明日验证条件，保存阈值、对象、时间和失效标准。

- 次日开盘前：竞价核验按五个时点读取真实状态，记录成功、部分成功或失败。

- 开盘后：将竞价与实际开盘、盘中板块和核心股反馈回写到下一次复盘。

- 先看当前周期和数据更新时间，确认自己看到的是什么时点。

PEG 估值把价格、前瞻 PE 和利润增长放在一起，帮助用户判断“资料是否足够计算”，而不是给出脱离口径的估值结论。

上游是财务和价格数据，下游是个股研究、AI 解释和资料补充；分支按市场横截面、单股三项数据、完整性和缺口提示拆开。

### 核心功能

PEG 估值把现价、PE、盈利增长、来源和适用性放在同一页面。它是估值辅助工具，不是独立投资结论。

## 附录｜原展示首页的完整阅读入口

原展示仓库的首页、宣传页、旧版说明和截图清单全部保留。本附录把静态首页放在新产品模块之后，方便继续浏览；当前功能以正文说明为准。

### 首页开场｜把行情、研究、验证放进一条可回看的工作流

原首页从实时行情、指标和复盘出发，连接策略筛选、回测、资讯、估值与 AI 辅助研判。首屏提供截图和完整说明两条阅读路径；展示仓库不含业务源码、数据库、密钥或生产配置。

### 截图展览｜先看真实产品，再看功能拆解

首页先陈列真实产品界面，再按模块展开功能、用法和截图位。实际图片须核对来源、账号信息与功能状态；未补图的位置不使用宣传插画冒充实拍。

### 研究流程｜发现、研究、验证、回看

发现：工作台、自选、板块、指数与排行确认市场状态。研究：指标、复盘、估值、资讯与 AI 拆解证据。验证：策略、回测和质量统计核对历史窗口。回看：从模拟、档案、来源时间和数据状态返回事实。

### 模块导航｜从入口到最小功能

### 技术与架构｜数据先成为事实，再成为结论

首页分别介绍前端、后端、数据、研究与 AI、部署和术语。架构图串起来源、接入、计算、接口与页面；正文继续说明各项技术落地在哪些功能，以及模块之间怎样衔接。

### 原首页的技术分组

前端：HTML、CSS、JavaScript 与 ECharts 负责结构、交互、图表和响应式页面。后端：Python、FastAPI、Uvicorn、REST API 和异步任务承接页面请求。数据与存储：Futu OpenD、SQLAlchemy、SQLite 和缓存管理来源、保存与时效；原首页也列有 baostock，但现阶段仅在形态扫描方案中评估，不写成已经上线的数据源。

研究与 AI：多周期指标、回测、PEG、BYOK 和 Agent 各有独立职责。部署：原首页展示 Linux、nginx、systemd、HTTPS 和 Cloudflare Pages 等技术方向；当前动态站仍由 Windows 本机、Uvicorn 与 Cloudflare Tunnel 提供，不把规划中的 Linux 迁移写成已完成。术语：API、As-of、BYOK 等另有通俗解释。

### 架构图｜四层串联，四种数据状态

行情与资讯源进入数据接入和事实层，保留来源、时间、标的、周期与状态；指标、复盘、估值、策略和回测在研究层计算，再由 FastAPI、JavaScript 和 ECharts 呈现。页面分别说明实时、缓存、历史回补与不可用：缓存命中不等于实时报价，缺少可信口径时显示受限状态。
